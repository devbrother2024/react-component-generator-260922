## 개요

- 무엇을, 왜 변경했는지 핵심만 bullet 2~4개로 작성한다. "무엇을 했는지"보다 "왜 필요했는지"에 무게를 둔다.

## 변경 사항

- 주요 변경 파일/기능을 bullet로 나열한다.
- 사용자에게 보이는 동작 변화가 있다면 명시한다.

## 테스트

- [ ] `bun run lint`
- [ ] `bun run test`
- [ ] `bun run build`
- 수동으로 확인한 시나리오가 있다면 체크리스트 형태로 추가한다(예: "- [ ] 프롬프트 500자 초과 시 에러 메시지 확인").

## 참고 사항

- 리뷰어가 알아야 할 배경, 트레이드오프, 후속 작업, 알려진 제약이 있다면 적는다. 없으면 이 섹션은 생략한다.
