# create-pr: GitHub PR 생성

현재 브랜치의 변경사항을 분석하고, 저장소 언어 맥락에 맞는 템플릿으로 PR 본문을 작성해 `gh pr create`로 PR을 생성한다.

이 스킬은 격리된 서브에이전트(`context: fork`)에서 실행된다. 즉, 이 스킬을 호출한 상위 에이전트의 대화 맥락과 무관하게 아래 절차를 스스로 완결시켜야 한다 — 특히 Step 1의 저장소 상태 파악을 생략하지 마라.

**push와 PR 생성은 원격 저장소에 공개되는, 되돌리기 어려운 행위**다. 아래 절차를 순서대로 지키고, 애매한 상황(예: 어떤 커밋까지 포함할지 불분명함, main에 직접 push해야 하는 상황)에서는 진행을 멈추고 사용자에게 확인을 구한다.

## 워크플로우

### Step 0: 저장소 지침 확인

저장소 루트의 `AGENTS.md`/`CLAUDE.md`에 PR 작성 규칙(제목 형식, 템플릿, 브랜치 전략 등)이 명시되어 있으면 그것을 최우선으로 따르고, 이 스킬의 기본 규칙은 그 지침이 다루지 않는 부분에만 보충으로 적용한다.

### Step 1: 현재 상태 파악

다음을 병렬로 확인한다:

- `git status` — 추적되지 않은 파일 포함 현재 상태
- `git branch --show-current` — 현재 브랜치
- 현재 브랜치가 원격 브랜치를 추적 중인지, 추적 중이라면 최신 상태인지
- `git log --oneline -20`, `git diff [base-branch]...HEAD` — base 브랜치(보통 `main`)에서 갈라진 이후의 전체 커밋 이력과 변경 내용. **가장 최근 커밋만 보지 말고 PR에 포함될 모든 커밋을 확인한다.**

커밋되지 않은 변경사항이 있다면:

- `.claude/skills/commit/SKILL.md`가 있으면 그 규칙을 따라 커밋한다.
- 없으면 저장소의 최근 커밋 스타일(언어, prefix 등)을 따라 논리적 단위로 커밋한다.

### Step 2: 브랜치 확인 및 Push

- 현재 브랜치가 `main`/`master`라면 새 브랜치를 만든다. 직접 push하지 않는다.
- 브랜치가 원격에 없거나 최신이 아니면 push한다(`-u` 필요 시 사용).
- **강제 push(`--force`)는 사용자가 명시적으로 요청하지 않는 한 사용하지 않는다.**

### Step 3: 템플릿 선택

기본값은 한국어 템플릿(`references/pr-template-ko.md`)이다. 아래 신호를 근거로 영어 기반 오픈소스 프로젝트인지 판단하고, 그렇다면 영문 템플릿(`references/pr-template-en.md`)으로 전환한다:

- `README.md`, `CONTRIBUTING.md` 등 저장소 대표 문서가 영어로 작성되어 있다.
- `git log`로 확인한 최근 커밋 메시지가 대부분 영어다.
- (참고 신호) GitHub 저장소가 외부 기여자를 받는 퍼블릭 오픈소스 프로젝트로 보인다(라이선스 파일, 이슈/PR 템플릿 등 영어 기여 가이드 존재).

이 판단은 저장소 전체의 기본 언어에 대한 것이지, 이번 변경사항 설명이 어떤 언어인지가 아니다 — 한국어 프로젝트에서 영어로 커밋 메시지를 한두 번 썼다고 영문 템플릿으로 바꾸지 않는다. 사용자가 "영어로 PR 써줘" 등으로 명시적으로 언어를 지정하면 그 지시가 이 판단보다 우선한다.

### Step 4: PR 본문 작성

- 선택한 템플릿 파일을 읽고, Step 1에서 파악한 커밋 이력·diff를 바탕으로 각 섹션을 채운다.
- 템플릿에 없는 섹션을 새로 만들거나 순서를 바꾸지 않는다. 내용이 없는 섹션(예: "참고 사항"/"Notes")은 템플릿 안내대로 생략한다.
- PR 제목은 70자 이내로 간결하게 작성하고, 상세 내용은 본문에 담는다.
- 현재 세션이나 저장소 지침에서 커밋/PR에 특정 attribution 푸터(예: `Co-Authored-By`, `Generated with ...`)를 요구했다면 PR 본문 맨 끝에 그대로 덧붙인다. 별도 지침이 없으면 생략한다.

### Step 5: PR 생성

- `gh pr create --title "..." --body "$(cat <<'EOF' ... EOF)"` 형태로, heredoc을 사용해 본문을 전달한다(따옴표/특수문자 이스케이프 문제를 피하기 위함).
- draft 여부, base 브랜치 등 사용자가 명시한 옵션이 있으면 반영한다. 명시하지 않았다면 기본 브랜치를 base로 사용한다.

### Step 6: 결과 보고

- 생성된 PR URL을 사용자에게 전달한다.
- Step 1~2에서 대신 처리한 것(자동 커밋, 새 브랜치 생성, push 등)이 있다면 무엇을 왜 했는지 함께 보고한다.
